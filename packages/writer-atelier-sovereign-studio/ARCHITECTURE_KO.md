# 작가공방 소버린 스튜디오 — 전체 아키텍처

`Router → 최소 진단/설계 전문가 → 현재 장면 전문가 → Single Writer → 독립 편집위원회 → 국소 수리 → Source-Blind Release → Dossier`

## 1. 진단 우선
문제가 불명확하면 `novel-story-sense`가 증상을 근본 원인 후보로 좁힌다. 바로 Writer를 부르지 않는다.

## 2. 선택적 거시 전문가
시리즈·장르·캐릭터/관계 아크·복선·AU·크로스오버·세계관·서브플롯·결말 등 현재 단계에 필요한 Skill만 로드한다.

## 3. 장면 실행 계층
정사, 상태, 캐릭터 수행, 장면 인과, Scene/Sequel, 대사, 감각/공간, 액션이 **현재 장면에 실제 영향을 줄 때만** 개입한다.

## 4. 단일 Writer
`novel-fiction-prose`만 전체 산문을 작성한다. 설계 전문가와 Critic은 본문 전체를 순차적으로 덮어쓰지 않는다.

## 5. 독립 편집위원회
17개 독립 검수 역할이 서로의 의견을 보기 전에 자기 관점으로 읽고, `chief-editor`가 finding만 받아 충돌을 조정한다. 신규 독자·장르 베테랑·정사 감수자·미스터리 공정성 감사자처럼 **입력 정보량도 다르게** 유지한다.

## 6. 수정 예산
hard fact → continuity/causality → reader blocking → local prose 순으로 최소 수정한다. 취향 수준이거나 수정할수록 voice가 평평해지면 멈춘다.

## 7. 장기 상태 엔진
복선, 지식, 관계, 성장, 상대 반격, 독자 부하, 결말 부채를 별도 스키마로 추적한다. 계획과 승인 본문이 충돌하면 승인 본문을 기준으로 계획을 갱신한다.
