# GitHub 소설 Skill 심층 조사 — 2026-09-15

## 조사 목적
기존 마스터 길드가 장면·정사·연속성·장기 아크에 강한 반면, 실제 장편 상업작가와 편집실이 사용하는 미세 진단 축 중 빠진 것을 찾기 위해 GitHub 공개 fiction skills와 webnovel playbook을 비교했다.

## 핵심 발견
1. **진단 라우터가 따로 필요하다.** 문제가 “재미없다”로만 주어질 때 바로 산문을 다시 쓰면 원인이 섞인다. Story Sense 계열처럼 먼저 상태를 분류해야 한다.
2. **Scene과 Sequel의 리듬을 분리해야 한다.** 사건 뒤 반응·딜레마·결정이 사라지면 캐릭터가 리셋되고, 후속이 너무 길면 추진력이 죽는다.
3. **결말은 열린 부채의 결산이다.** surprising/inevitable의 균형, protagonist final choice, aftermath/new normal을 별도 검사해야 한다.
4. **독창성은 기능을 버리는 것이 아니다.** 흔한 표현 대신 같은 기능을 덜 흔한 형태로 옮기는 통계적 거리와 직교적 변주가 유용하다.
5. **세계는 주인공 성장에 동기화돼야 한다.** 공개 승리·새 능력·시간 점프 뒤 적·조직·시장·여론이 멈춰 있으면 장편의 세계가 게임 배경처럼 보인다.
6. **오리지널 세계관은 우회 노출이 중요하다.** 제도·문서·전문직·편향된 관점의 맹점을 통해 규칙을 보여주면 백과사전식 설명을 줄일 수 있다.
7. **캐릭터 차별화는 말끝보다 인지 패턴이다.** 무엇을 보고 어떤 증거를 믿고 어떤 비용을 무서워하는지의 차이가 더 강한 voice를 만든다.
8. **완성 원고는 역아웃라인이 필요하다.** 계획이 아니라 승인된 실제 산문에서 기능을 추출해 후속 계획을 재정렬해야 한다.

## 이번 패키지에서 새로 만든 독립 영역
Story Sense, Scene/Sequel, Opening Contract, Ending/Payoff, Cliche Transcendence, Character Distinctness, Antagonist Counterplay, Supporting Cast Ecology, Subplot Weaving, Oblique Exposition, Sensory Embodiment, Action Choreography, Mystery Fair-Play, Reader Cognitive Load, Progression Economy, World Response Escalation, Reverse Outline, Developmental Revision, Cultural Authenticity, Humor Timing.

## 사용 원칙
50개 Skill을 동시에 로드하지 않는다. 라우터가 현재 실패 원인과 작업 단계에 필요한 최소 집합만 부른다. 초고 전체를 쓰는 Writer는 계속 `novel-fiction-prose` 하나다.
